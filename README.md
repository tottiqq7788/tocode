# Tocode（app）

macOS 菜单栏文件管理器，Swift/AppKit 原生实现。

## 功能

- 左键菜单栏图标 → 弹出当前根目录树；悬停文件夹展开下级；未按修饰键时点击文件或文件夹复制「绝对路径」。
- 每个目录菜单底部固定提供「新增」：弹出小窗口输入文件名并选择常见格式（txt / md / csv / json / docx / xlsx / pptx / pdf），创建空文件；文件名不带扩展名时自动追加所选格式扩展名。
- 左键目录树已打开时，按住 `Option` 会实时切换为删除模式：底部「新增」变为「清空」，点击文件/文件夹改为删除；松开后恢复复制路径。清空或删除都会先弹确认窗口，确认后把对应内容移入废纸篓（可恢复）。
- 左键目录树已打开时，按住 `Command` 会实时切换为访问模式：底部「新增」变为「访问」，点击「访问」或文件夹条目会用访达打开该文件夹，点击文件则用默认应用打开。同时按住 `Option` 时仍为删除模式。
- 右键菜单栏图标 → 功能菜单：读取剪贴板、更改目录、重置初始目录、codex、mac、微信关联、设置、退出。
- 根目录保存在本机；已保存路径不存在时回退 `/Users/admin/Documents`。
- 开关、根目录、键盘映射、触控板和滚轮写入固定偏好域 `com.tocode.app`，不跟 Bundle ID 走。从旧域 `com.tocode.mac` 启动时自动迁一次。
- **设置 → 开机自启**（默认关闭）：把 Tocode 登记为系统登录项，开机后自动启动。菜单只显示系统里的实际状态；在系统设置里手动关掉后，下一次打开本菜单会跟着关闭。登记失败或需要批准时不会显示为已开启。
- **设置 → 导出配置 / 导入配置**：导出为 `.tocode`（JSON），只含键盘映射、触控板轻点、快捷键开关与滚轮。导入前确认，确认后整段覆盖这些项；根目录、开机自启、同步项目夹、拓展设置、微信凭据和密钥不会进出该文件。
- **设置 → 说明书**：弹出只读窗口，用 Tab 分页说明目录树、访达与目录、mac、微信、命令行和设置的用法；不改配置。
- **设置 → 对调垂直滚轮 / 对调横向滚轮**（默认关闭）：只反转物理鼠标滚轮对应轴向，**不改触控板**（含 Magic Mouse 表面等连续滚动）。不做平滑插值，也不改系统「自然滚动」。启用前请先退出 Mos，否则两边会互相抵消。与快捷键钩子相互独立：滚轮钩子故障不会拆掉 ⌘Q / ⌘X。
- **设置 → 显示/隐藏隐藏文件**：与访达共用 `AppleShowAllFiles`。左键目录树显示隐藏项时访达也显示，反之亦然。覆盖以 `.` 开头的条目，以及带 Finder hidden 属性的条目。
- 在访达中按 `⌘⇧.` 切换后，下一次打开 Tocode 菜单会跟随新状态。
- 从 Tocode 切换该选项会写入访达偏好并重启访达，使显示立即生效；写入或重启失败时恢复原状态。
- **访达目录初始化**（条件显示）：访达里用鼠标恰好选中一个项目时出现，不要求访达仍在前台。选中文件夹则设为左键根目录；选中文件则设为其父级文件夹。无选中、多选、权限失败或路径失效时不显示；点击时会再次校验，失败不改根目录。
- **设置 → x/v移动文件**（默认关闭）：仅当访达是前台应用时接管普通 `⌘X` / `⌘V`。文件上下文中 `⌘X` 会先变成访达复制；剪贴板 `changeCount` 变化且含文件 URL 后进入剪切预备。下一次 `⌘V` 改写为访达原生 `⌥⌘V`，移动到**访达当前窗口的目标目录**，不是 Tocode 的左键根目录。多文件、文件夹、重名冲突、跨卷、iCloud 和权限提示都由访达自己处理。重命名或文本框中的 `⌘X` 仍按文本剪切。其他应用的 `⌘X` / `⌘V` 完全不受影响。
- **设置 → 双击⌘Q**（默认关闭）：全局保护普通 `⌘Q`（不含 Shift / Option / Control）。第一次按下会被吞掉并提示「再次按 ⌘Q 退出 \<应用\>」；只有 2 秒内、目标仍是同一进程时，第二次才放行退出。超时或切换目标后重新计数。这是普通退出，不是强制退出：`⌘⇧Q`、`⌥⌘Esc`、鼠标点菜单「退出」、Dock / 活动监视器退出和 `kill` 都不会被拦截。按住产生的自动重复不算第二次。
- **设置 → ⌘Q强关访达**（默认关闭）：当访达是普通前台，或系统 Command-Tab 切换器当前选中访达时，普通 `⌘Q` 会关闭全部访达窗口并隐藏访达，**不会退出访达进程**。没有打开窗口时也会隐藏。目标无法识别时原样放行。与「双击⌘Q」同时开启时，第一次只提示「再次按 ⌘Q 强关访达」，2 秒内再按一次才关窗隐藏。

## mac（临时黑屏）

- 右键菜单栏图标 → **mac → 临时黑屏**：在每个显示器上显示全屏纯黑无边框覆盖窗口，不显示任何文字；按下任意键盘按键或鼠标按键后解除。
- 按下任意键盘按键或鼠标按键后，所有覆盖窗口立即关闭；再次点击菜单项而黑屏已显示时不会重复创建。
- 这是自包含叠加层，不依赖快捷键/滚轮钩子，也不需要辅助功能权限。菜单项是一次性操作，不保留开关状态。

## mac（触控板）

- 右键菜单栏图标 → **mac → 触控板 → 三指轻点 / 四指轻点 / 五指轻点**。已绑定的菜单项打勾，tooltip 显示快捷键符号或功能名。
- 点击任一手势后弹出编辑窗口，目标由分段控件在「映射快捷键」与「映射功能」之间选择，来回切换不会丢失任一页已填的内容。可保存、覆盖或清除该手势唯一对应的目标。
- **映射快捷键**：录入一个组合键。精确指数量的短时、低位移、完整抬起轻点后合成一次该组合键。
- **映射功能**：与键盘映射使用同一份按右键菜单分组的一次性动作与开关目录。系统项是「向左切换桌面 / 向右切换桌面」，实现为发送系统自身的 `⌃←` / `⌃→`（含方向键自带的 Fn）。Tocode 项与跳过项、开关只翻转一次、同步项目夹开启时不改手动根目录，均与键盘映射相同。
- 滑动、长按、指数量不符或未配置不会触发。合成事件带内部标记，不会再次进入键盘重映射。
- 无绑定时停止触控监听。监听或按键合成失败时配置仍保留并弹系统通知，键盘映射、滚轮与既有快捷键不受影响。
- 配置持久化在本机 UserDefaults 键 `tocode.trackpadShortcut.{3,4,5}FingerTap`。旧版本保存的纯快捷键配置无需迁移即可继续读取和使用。

## mac（键盘映射）

- 右键菜单栏图标 → **mac → 键盘**：子菜单固定提供「新增」，其下按名称列出已保存的映射规则，菜单项 tooltip 显示「源 → 目标」。点击任一规则可编辑或删除。
- 编辑窗口包含名称、源快捷键与目标。源快捷键框点击后监听一次键盘组合；目标由分段控件在「映射快捷键」与「映射功能」之间选择，来回切换不会丢失任一页已填的内容。
- **映射快捷键**：再录入一个组合键。命中源时吞掉原输入，只合成一次该目标组合键。
- **映射功能**：按右键菜单分组选择一个一次性动作或开关切换。系统项是「向左切换桌面 / 向右切换桌面」，实现为发送系统自身的 `⌃←` / `⌃→`（含方向键自带的 Fn），因此依赖「系统设置 → 键盘 → 键盘快捷键 → 调度中心」里的「向左移动一个空间 / 向右移动一个空间」处于开启状态。Tocode 不读取也不修改该系统偏好；若它被关闭或被改键，功能会静默失效。全屏应用或只有一个桌面时系统本身也不会切换。
- Tocode 项包括访问路径、复制路径、目录初始化、显示/隐藏隐藏文件、x/v移动文件、⌘Q强关访达、读取剪贴板、重置初始目录、同步项目夹、微信文件位置、临时黑屏、对调垂直/横向滚轮、双击⌘Q、开机自启与退出。开关一律按一下翻转当前状态。不提供更改目录、绑定微信、AK密钥、触控板配置、键盘配置或模型切换。
- 同步项目夹开启时，映射触发「读取剪贴板 / 重置初始目录 / 目录初始化」不会改手动根目录。临时黑屏已显示时，映射钩子放行所有按键，以便覆盖窗按任意键解除。
- 名称不能为空；名称与源快捷键在规则间各自唯一。仅当目标是桌面切换时，源快捷键不能与该功能自身的触发键相同（例如源 `⌃←` → 目标「向左切换桌面」），但把 `⌃←` 重映射为其他目标是允许的。
- 命中源快捷键时吞掉源 `keyDown` / `keyUp`；自动重复只吞掉不重复执行。桌面切换的合成事件带内部标记，既不会再次进入重映射，也不会触发双击⌘Q等既有保护。
- 没有规则时不安装键盘事件钩子，需要**辅助功能**权限。权限被拒、钩子创建失败或钩子无法恢复时，规则仍然保留并弹系统通知，触控板、滚轮与既有快捷键不受影响。
- 规则持久化在本机 UserDefaults 键 `tocode.keyboardShortcutMappings`。旧版本保存的「目标为组合键」的规则无需迁移即可继续读取和使用。

## 设置（拓展设置）

- 右键菜单栏图标 → **设置 → 拓展设置**：列出功能类型开关。类型默认关闭；只有勾选后，右键菜单才显示该类型专用项。
- **AK**（默认关闭）：勾选后才显示 **codex** 下的模型切换子菜单，以及 **设置 → AK密钥**。关闭只隐藏这两项，不删除已保存的密钥，也不影响 CLI / 微信命令。

## 设置（AK密钥）

- 仅当 **设置 → 拓展设置 → AK** 勾选时出现。右键菜单栏图标 → **设置 → AK密钥**，在隐藏输入框中输入新密钥，点击「保存」。旧密钥不会回填；取消不修改配置。
- 一次保存同步 OpenCode、pi、CC Switch 当前 Anker Codex 服务商及其代理恢复备份、Hermes。pi 的 Anker `apiKey` 配置为每次请求动态读取 OpenCode 中的安克密钥（使用 macOS 自带 plutil，不依赖额外脚本）；已有的 pi / OpenCode Anker API 认证覆盖项也会同步。
- Hermes 接入安克网关，默认使用 **DeepSeek V4 Pro**；密钥保存在 `.hermes/.env` 的 `ANKER_API_KEY`，模型配置引用该变量。其他环境变量、微信绑定、其他服务商和 Codex / pi / OpenCode 的模型选择保持不变。
- 保存前检查全部配置，捕获写入或复核失败时回滚本次修改；遇到并发修改时不会覆盖其他程序的新内容，恢复失败会明确提示。更新后的凭据文件权限为 `0600`，密钥不进入日志、通知或命令参数。
- Codex 的后续请求通过 CC Switch 读取更新后的服务商凭据，不改本地代理令牌，也不重启 Codex。pi 后续请求动态读取新密钥，若此前使用过手动登录凭据可打开 `/model` 重新加载配置；已打开的 Hermes / OpenCode 会话需重新加载或重开。Tocode 不会自动中断正在执行的任务。
- 此入口只管理当前用户的默认配置。配置缺失、当前服务商不匹配、非安克网关、CC Switch 故障转移开启或 Hermes 自定义凭据池覆盖时，会停止保存并提示检查。
- 保存动作不发送网络请求，因此成功表示四工具本地配置写入完成；新密钥的远端有效性与额度由后续实际请求确认。跨文件和 SQLite 的恢复针对可捕获故障，不保证断电或进程被强杀时整体原子提交。

## codex（同步项目夹）

- 右键菜单栏图标 → **codex**：显示 Codex 当前选中的本地项目名称与根目录；检测失败显示「未检测到 Codex 项目」。
- **同步项目夹**（默认关闭）：开启后左键目录树每次弹出时跟随 Codex 当前项目的根目录；关闭后恢复手动根目录。
- 开关开启时，「读取剪贴板」「更改目录」「重置初始目录」「访达目录初始化」四项置灰不可点击；关闭后恢复。
- 只读本机 Codex 全局状态文件 `~/.codex/.codex-global-state.json`，绝不写回；状态不可读或没有有效项目时，左键自动回退手动根目录（开关与置灰状态仍以开关为准）。

## codex（模型切换）

- 仅当 **设置 → 拓展设置 → AK** 勾选时出现。右键菜单栏图标 → **codex**：在项目与同步开关下方显示当前 Codex 用户级模型的友好名称，例如 `GPT-5.6 Sol`。该名称本身就是模型子菜单入口，不显示“模型切换”字样。AK 关闭时不显示该入口。
- 每次展开模型子菜单都会使用 CC Switch 当前 **Anker AI Router** Provider 的凭据，实时请求 `https://ai-router.anker-in.com/v1/models`；不会使用旧缓存伪装实时结果。加载失败时可直接重试。
- 规范中确认兼容 Codex `/responses` 的主模型可直接选择；尚未验证的文本模型带警告标记并要求再次确认；图片、视觉、标签以及明确不兼容 `/responses` 的模型会显示在列表中，但不可选择。
- 选择模型后，Tocode 只替换 CC Switch 当前 Codex Provider 模板和 `~/.codex/config.toml` 中唯一的顶层 `model` 值。两份配置必须同时写入并复核成功；任何失败都会回滚，且不会退出 Codex。
- 切换成功后固定等待 **2 秒**，随后直接向所有 `com.openai.codex` 主应用进程发送 `SIGKILL`，不请求正常退出、不等待 Codex 保存或确认。旧进程消失后自动重新打开 `/Applications/ChatGPT.app`。
- 强制退出会中断正在执行的任务，也可能丢失尚未持久化的界面状态。模型配置已经成功保存时，即使重新启动失败，也不会回滚到旧模型。

## 微信关联

- 右键菜单栏图标 → **微信关联 → 绑定微信**：默认浏览器会打开扫码页面。使用具备 iLink Bot 资格的个人微信扫码并确认后，菜单项显示勾选。
- 绑定凭据保存在应用数据目录 `~/Library/Application Support/com.tocode.app/wechat-credential.json`，权限 `0600`，仅当前用户可读，避免临时签名导致每次启动都触发钥匙串授权。应用启动时会自动恢复监听；普通断网、超时或微信服务暂时故障不会取消绑定，只有服务端明确返回 `401/403` 才会清除凭据并通知重新绑定。
- 绑定后再次点击「绑定微信」可重新扫码。新绑定确认并安全保存前，旧绑定仍保持运行；扫码失败或过期不影响旧绑定。
- Tocode 只接收**发给已授权 iLink Bot 的新消息**，不会读取个人微信账号里的其他私聊、群聊或历史记录；普通消息不调用模型、不自动回复，只有 `.` 前缀命令和整条快捷输入（`{按键}` / `“文字”` 段序列）会按命令层约定回复执行结果。
- 收到的文字、语音转写、图片、文件和视频会归档到固定位置 `/Users/admin/Documents/wechat`。只有 iLink 实际提供媒体下载描述时才保存原文件。
- 每天使用一个 `yyMMdd` 目录和一个 Markdown 文件。例如 2026-09-07 写入 `260907/wechat260907.md`；附件按本机收到时间重新命名，既有文件永不覆盖。
- **微信关联 → 文件位置**会创建并在访达打开归档目录。

微信 iLink 目前可能受内测资格与服务端协议变化限制。无法扫码或账号没有入口时，不代表 Tocode 能绕过资格读取普通微信聊天。

## 命令层（CLI 与微信 `.` 前缀）

Tocode 提供两层统一命令入口，共享同一个白名单执行器（不做任意 shell 执行）。

### CLI

```bash
bash scripts/build.sh        # 同时产出 build/Tocode.app 与 build/tocode
./build/tocode help          # 打印命令表
./build/tocode status        # 汇总根目录、开关、微信、Codex 状态
```

CLI 通过本机 Unix domain socket 转发给**常驻 Tocode 进程**执行；Tocode 未运行时打印明确错误并以非零退出码结束。socket 位于 `~/Library/Application Support/com.tocode.app/tocode.sock`，权限 `0600`，仅本用户可用。`help` / `commands` 是本地命令，无需常驻进程。

Tocode 首次启动后，会自动把 CLI 安装到 `~/.local/bin/tocode`（该目录已在 PATH 中），之后可直接在终端运行 `tocode ...`。

主要命令：`help`（同 `commands`）、`status`、`root get|set|choose|reset|init-from-finder`、`codex status|sync|model|model list|model set`、`wechat status|bind|location|send`、`blackout`、`login on|off|toggle`、`wheel vertical|horizontal on|off|toggle`、`hidden on|off|toggle`、`shortcut finder-move|double-cmdq|finder-cmdq on|off|toggle`、`quit`。开关类命令的 `on|off|toggle` 可互换使用；每条命令都会返回结果，不静默执行。

`tocode wechat send [--to <user_id>] [--text <文字>] [文件...]` 通过**当前已绑定**的微信 Bot 主动发消息：默认发给最近一条入站会话；`--to` 只能指定曾经入站过的用户。文字先发，文件按参数顺序各发一条；`jpg/jpeg/png/gif/webp` 作为图片，其余作为附件。单文件不超过 20MB；失败即停，已发出的不回滚。出站内容不写入 `wechat*.md`。Tocode 未运行或未绑定时失败。

### 微信 `.` 前缀命令

微信监听循环中，若一条消息**第一项是文本且 trim 后以 `.` 开头**，则整条消息被判定为命令：

- 命令体复用 CLI 解析器；`.lshp` 是 `blackout` 的别名，`.commands` / `.help` 可查询全部命令。
- 命令消息**不写入 `wechat*.md`、不保存附件**；执行结果通过 `sendmessage` 回复到原会话，回复信息同样不作为正式归档记录。
- 未知命令、参数错误或执行器失败会回复错误信息并正常消费，不打断监听循环，也不重试。
- 命令去重键与普通消息同一来源，执行成功或失败都不重复执行。

普通微信消息仍保持只接收、不回复、不调模型；只有 `.` 前缀命令和快捷输入会按上述约定回复执行结果。

### 微信快捷输入

整条消息第一项是文本且 trim 后**不以 `.` 开头**时，若能从左到右拆成一段或多段 `{按键}` / `“文字”`（段间只允许空白，拆完没有剩余），则按与 `.` 命令相同的消费规则执行：

- 不写入 `wechat*.md`、不保存附件；执行前先写入去重 key 并推进游标。
- 按段从左到右依次注入；整段成功或在第一处失败都 `sendmessage` 回复原会话；失败后不再执行后续段，已执行的前段不回滚。
- `{...}` 去括号后按 `+` 分段，必须恰好一个主键，前面是修饰键。修饰键别名：`cmd`/`command`/`⌘`，`opt`/`option`/`alt`/`⌥`，`shift`/`⇧`，`ctrl`/`control`/`⌃`，`fn`。主键包括 `space`、`enter`/`return`、`tab`、`esc`、方向键、`a`–`z`、`0`–`9`、`f1`–`f12` 等。
- 文字段必须用中文引号 `“”` 包裹；空 `“”`、无法识别的按键、超过 16 段或全部文字合计超过 500 字时整条失败且一段都不注入。
- 未包裹的裸文本（如 `你好{enter}`）、ASCII 直引号或半截括号仍是普通消息，照常归档、不回复。
- 需要辅助功能权限；拒绝则回复失败，绑定与监听不受影响。不新增 CLI 命令。

示例：`{space}`、`{cmd+space}`、`“你好”`、`“你好”{enter}`。

## 权限

首次使用「访达目录初始化」时，系统可能请求「控制访达」。请允许；拒绝后该选项不会出现。

「mac → 临时黑屏」为纯覆盖窗口实现，不需要辅助功能权限，也不依赖既有快捷键/滚轮钩子。

开启任一快捷键开关、滚轮对调开关，或保存第一条键盘映射规则时，只会显式请求**辅助功能**。该授权用于读取 Finder / Dock 切换器焦点，以及创建可拦截、改写按键和滚轮的事件钩子；不会另行申请「输入监控」或独立 PostEvent 权限。关闭访达窗口复用已有的「控制访达」自动化授权：

1. 右键菜单栏图标 → 设置 → 打开对应开关。
2. 若系统打开授权提示，请到「系统设置 → 隐私与安全性 → 辅助功能」中允许 Tocode，再点击一次开关。
3. 事件钩子实际安装成功后，当前菜单项会立即显示 `checkmark.circle.fill`；失败时保持 `circle`。
4. 拒绝授权、钩子创建失败或钩子无法恢复时，开关保持关闭，**所有按键原样放行**，不会锁死键盘或退出通道。

三项快捷键默认关闭；全部关闭时不会安装键盘事件钩子。两项滚轮对调默认关闭；全部关闭时不会安装滚动钩子。键盘映射使用自己独立的键盘事件钩子：没有映射规则时不安装，与上述开关互不依赖，任一侧故障都不会拆掉另一侧。

本地构建使用稳定的 designated requirement，避免 ad-hoc 签名默认绑定每次变化的 `cdhash`，导致重新编译后已有的访达自动化授权静默失效。首次从旧构建迁移到稳定签名时仍需重新允许一次；辅助功能授权同样绑定该稳定身份。
